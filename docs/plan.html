An open-source Rust CLI (then TUI and menu bar) that manages NordLynx WireGuard tunnels on macOS without breaking Tailscale or Headscale. Grown from the working nord-wg script, diagnosed and proven on 2026-10-30.

1. Problem and proven fix

A full WireGuard tunnel on a Mac moves Tailscale's own underlay traffic (control server, DERP relays, direct-peer UDP) into the VPN. Tailscale's netcheck then reports UDP false and the tailnet dies, even though the 100.64.0.0/10 route is correct and Nord passes UDP, TCP and MTU normally.

Proven fix (tested with Kenya and US servers): host routes via the physical gateway for the control server IP and all DERP IPs. Tailnet recovers, exit IP stays the VPN's. The root cause (why Nord drops Tailscale's packets) is still unexplained and is listed as a risk.

Also learned: the Nord Mac app and wg-quick with DNS= both clobber MagicDNS; the official nordvpn CLI is Linux only; South Africa is ZA.

2. Landscape

NordGen (mustafachyi/NordVPN-WireGuard-Config-Generator, GPL-3.0, 459★, pushed 2026-10-23) is a Python CLI plus a Go port and a Cloudflare Worker web UI. It takes a 64-hex access token, calls the credentials endpoint with Bearer token:<token> to get nordlynx_private_key, filters wireguard_udp servers, sorts by load then distance, and writes .conf files per country and city. It is a config generator: no connect/disconnect, no macOS or Tailscale handling, and --token leaks via argv.

API endpoints used by these tools: GET /v1/users/services/credentials (auth), GET /v1/servers/recommendations and /v1/servers?filters[...] (no auth), GET /v1/helpers/ips/insights (caller geo). They are undocumented by Nord and can change.

No sudo prompt per switch. Design in section 5.

clap-generated completions and man page; short aliases.

AGREED Network-change watcher

Re-apply bypass routes when the gateway changes. Push events from the system, not polling.

AGREED Auto-gen on up

A missing or week-old config is rebuilt by up itself. No separate gen step needed.

Proposed earlier (pick last-used or fastest country); not agreed. Left out unless you say otherwise.

4. Architecture

From your template note: a Cargo workspace of 3 to 6 crates, hexagonal-lite (ports as traits in the core, adapters outside), thiserror in libraries and anyhow only in the binary, generics over dyn, no DDD ceremony. Crate boundaries are compiler-enforced; the platform adapter is the one boundary that is a real contract (a Linux adapter could follow).

wglane-cliclap commands, ratatui TUI (feature), output formatting. Binary. Wires adapters.

  • Tunnel engine: v0.1 shells out to wg-quick (brew dependency), as the proven script does. Later option: drive wireguard-go or boringtun directly.
  • Testing: hand-written fakes for the ports; insta snapshots for rendered configs and help text; recorded API fixtures.
  • Config files are written 0600; key material is zeroized in memory.

5. Passwordless privilege

Bringing up a utun interface and editing routes needs root. You asked not to sign with sudo each time.

OptionHowSecurityEase for open source
A. Root-owned helper + sudoersOne-time sudo wglane install-helper copies a helper binary to a root-owned path and adds a sudoers.d rule for that binary only. Helper accepts fixed verbs (up, down, bypass) and reads configs only from a root-owned directory.Sound if the helper is root-owned (not the user-writable Homebrew copy), no wildcards, strict argument validation.Good. One command, no Apple signing.
B. Launchd root daemonDaemon plus a unix-socket protocol; CLI becomes a client. The proper long-term route (as Tailscale's tailscaled).Strongest, and the right base for a menu bar app.Heavier. Signed daemon and Login Items approval need a $99 Apple Developer ID.
C. Plain sudo, cachedKeep prompting; rely on sudo's timeout.No new attack surface.What you want to leave.
Decided: option A now, daemon (B) later. B is not needed now because its main reason was a menu bar, which is out of scope. Ship A in v0.1, designed so the helper's verb set becomes B's socket protocol later. A sudoers rule on a user-writable binary is a local privilege escalation, so the helper must be copied to a root-owned location at install time. This needs a security review before release.

7. CLI design and DX

A new user should learn the tool from the tool. Rich help, not a bare usage line.

wglane up US            connect (switches if already connected)
wglane down             disconnect and remove bypass routes
wglane status [--json]  country, exit IP, tailnet check, routes
wglane servers [CC]     ranked servers, by load and distance
wglane gen CC...        write configs without connecting
wglane doctor           check wireguard-tools, tailscale, helper, token
wglane watch            re-apply bypass routes on network change
wglane tui              full-screen dashboard
wglane completions SH   shell completions (zsh, bash, fish)
  • after_help examples on every subcommand; a short "why Tailscale breaks and what we do" in --help of up.
  • doctor prints exactly what to run to fix each failed check.
  • Errors say what to do next. Color via anstyle; color-eyre in the binary; tracing with -v.
  • xtask generates man pages and completions; cargo-dist publishes a Homebrew tap formula.

8. Phases

  1. Parity and safety

    Workspace, core ports, Nord client, auto-gen on up, token sources (env, config-dir file), up/down/status/gen, Tailscale bypass, helper install (option A), doctor. Done when: it reproduces today's script on a clean Mac and status reports a passing tailnet check.

  2. Hands-off

    Network-change watcher, completions, aliases, man page, Homebrew tap via cargo-dist, README with the Tailscale explanation. Done when: switching Wi-Fi keeps the tailnet alive with the VPN on.

  3. TUI

    wglane tui: server list, connect, stats card with latency sparkline. Done when: every CLI action is reachable from it.

  4. Later: menu bar and daemon

    Not planned now. If wanted, revisit the root daemon (option B) first.
